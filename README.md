# pi-interrupt-control

**简体中文** | [English](README.en.md)

一个 Pi 扩展：用句点继续任务，用 `/new-continue` 在新会话接手未完成工作，在模型请求失败时先重试，再决定是否交给 Pi 回退处理。

## 功能

- 单独输入 `.` 或 `。`，继续最近尚未完成的任务。
- `/new-continue` 生成交接摘要，在新会话中自动继续；空会话会回溯同工作区的历史。
- 每个主模型请求默认额外重试 **3 次**，间隔 **3 秒**。
- `/set-retry` 调整当前会话的额外重试次数和间隔；负数表示耗尽后直接停止。
- 重试期间只显示最新提示，结束后清理提示并保留一条重试总结；手动取消时不留总结。
- 不对其他会话、压缩、摘要或缓存预热请求额外重试。

## 安装

需要 **Pi 1.5.0 或更新版本**和 Node.js 22.19.0 或更新版本，无需构建。所有功能均不支持 Pi 1.4.x 及更早版本。

### GitHub 安装

```sh
pi install git:github.com/llc2214926/pi-interrupt-control
```

### 本地安装

```sh
pi install /绝对路径/pi-interrupt-control
```

安装后重启 Pi，或在已有会话中执行 `/reload`。

只在一次启动中体验，且不加载其他扩展：

```sh
pi --no-extensions --extension /绝对路径/pi-interrupt-control/src/index.ts
```

## 用法

### 继续任务

单独发送：

```text
。
```

英文句点 `.` 也可以，前后空白会被忽略。扩展发送隐藏的继续指令：空闲时启动下一轮，运行中排队，不抢先打断当前工作。它仍会进入模型上下文，并非不留记录。

包含其他文字、多个句点或图片的输入保持原样；其他扩展注入的消息不会被转换。

### 在新会话继续

```text
/new-continue
```

原 `pi-session-manager` 的 `/s-new-continue` 已迁移至本扩展，并更名为 `/new-continue`；旧命令不再注册。无需安装 `pi-session-manager`。

- 不接受参数。需要 Pi 交互终端（TUI）、可用模型及凭据。请等待当前任务和消息队列结束，或先按 Esc 停止；忙碌时只提示，不强行中断。
- 使用当前分支的有效历史，保留压缩摘要及上下文编辑，不混入其他分支。只有系统提示、模型设置或扩展状态的会话视为空。
- 当前会话为空时，优先回溯同工作区的父会话；没有可用父会话时，在当前会话目录中按创建时间向前查找。跳过空白、缺失或损坏的记录，避免循环；不读取归档，不接手其他工作区的任务。没有可用内容时不创建新会话。
- 当前模型生成中文交接，包含目标、约束、决定、已完成工作与证据、待办、阻塞及下一步。生成期间按 Esc 取消；模型明确返回无待办时也不新建会话。
- 原会话保留。新会话先保存交接、来源和摘要用量，再自动继续；自动发送失败时，可手动发送“继续”。交接不会替换新会话的系统提示或授予额外权限。

**费用与隐私：** 会产生摘要请求及后续执行的模型费用。有效历史中的用户消息、文件片段和工具输出会以文本发送给当前模型提供方；排除原始 system 消息不等于脱敏。请确认提供方适合处理这些数据。

**限制：** 摘要可能遗漏细节，图片不会完整迁移，必要时回看原会话。受模型上下文限制；摘要请求失败、输出不完整或为空时不切换会话，也不静默截断历史。历史文件本身的符号链接、超过 256 MiB 或不支持的会话格式会被拒绝。

### 设置重试

```text
/set-retry          查看当前设置
/set-retry 10 5s    额外重试 10 次，每次间隔 5 秒，耗尽后交给 Pi
/set-retry -3 2s    额外重试 3 次，每次间隔 2 秒，耗尽后停止
/set-retry 0        关闭本扩展的额外重试
/set-retry 3        恢复默认次数和 3 秒间隔
```

- 次数必须是 `-100` 到 `100` 的整数，表示**首次请求之外**的次数。
- 间隔带小写 `s`，支持小数（如 `0.5s`），范围为 `0.001s` 到 `2147483.647s`；省略时恢复为 `3s`。
- 非法参数不会改变已有设置。
- 设置只保存在当前扩展运行时的会话内存中；重载扩展、重启 Pi 或创建新会话后恢复默认值，不写入全局配置。

## 兼容性与限制

- 优先重试需要 Pi 提供 `ModelRegistry.runtime.streamSimple`。缺少该接口时会明确报错，不能启用优先重试；句点续接仍可使用。
- 为避免失败响应中的半截工具调用被执行，回复会等一次请求完成后再显示，不逐字实时输出。
- 非负次数耗尽后仍可能触发 Pi 自带重试、压缩或其他回退扩展；`/set-retry 0` 不会关闭它们。负数耗尽后中止当前运行，不发起供应商切换。
- 所有模型请求错误都会先重试，包括认证错误和上下文超限；较大的次数和间隔会增加等待时间，也可能产生额外费用。
- 用户主动取消不会继续重试；本扩展不会自行切换模型或供应商。
